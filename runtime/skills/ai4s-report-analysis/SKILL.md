# AI4S 研判报告分析

## 目标

把检索线索转换为可核验的研判报告。先建立事实和证据，再做判断与组织，不用重复摘要或空泛套话填充篇幅。

## 证据整理

1. 为每条来源建立记录：标题、作者/机构、发布日期、来源类型、URL、可直接引用的事实和适用范围。
2. 至少交叉核对三类来源（原始论文或预印本、机构/项目官网、代码仓库/数据集；主题不适用时说明原因）。搜索结果摘要只能作为线索，不能替代正文。
3. 按 URL 和事件去重。把同一事实的多个来源合并，并保留最权威的来源和补充来源。
4. 给每个事实分级：`已证实`、`来源明确的推断`、`待核验`。只有前两类可以支撑正文判断；待核验内容放入待观察问题。
5. 工具失败、超时、未配置、代理地址、异常堆栈、空结果和内部文件名属于运行诊断，不得进入正式报告。证据不足时写“当前公开资料有限，暂未发现足够可靠的信息支持进一步判断”，并指出缺口。

## 章节契约

AI4S 研判报告默认必须按以下顺序输出十个独立章节。资料不足时保留章节并明确写资料缺口，不能删除章节或用空泛套话填充。每章只承担一种信息职责：

1. 事件概览：时间线、参与者、触发事件和可核验数字。
2. 科学问题：研究对象、假设、评价指标和约束。
3. 技术路线：模型/算法、数据、训练或实验流程、输入输出和工程实现。
4. 主要创新：逐条说明相对前序工作的变化，并绑定证据。
5. 论文团队与机构：作者、团队、机构、代表成果及关系。
6. 前序工作：按时间顺序说明继承、复用和变化。
7. 竞争路线：国内外路线在目标、方法、数据和公开结果上的差异。
8. AI4S 意义：从前文事实推导具体影响，避免“意义重大”“值得关注”等无证据结论。
9. 待观察问题：可验证信号、观察方法、时间窗口和当前不确定性。
10. 来源证据：集中列出引用编号、标题、机构/作者、日期和 URL。

每个主要章节应有 2—4 条具体事实或来源；如果证据不足，明确写资料缺口。事实、分析和限制分段书写，避免一段同时承担三种职责。一个来源可以支持多个章节，但不要复制相同段落。

完成前逐项检查十个标题是否存在，并检查 AI4S 意义和待观察问题中的每个判断是否紧跟事实或来源。

## 输出规则

- 先写一段由事实组成的摘要，再按章节展开技术和竞争关系，最后给出有边界的判断。
- 每个重要判断紧跟引用编号；引用必须能打开原始 URL。
- 不捏造论文、作者、数字、机构、项目、实验结果或图片。无法核实时使用保守表述。
- 生成 HTML 时使用语义标题、可读段落、必要的表格和来源链接。图表只有在数据足够且能表达明确关系时才使用。
- 完成前检查：章节是否错位或重复、每个判断是否有证据、来源 URL 是否完整、正文是否出现工具错误关键词（`failed to connect`、`127.0.0.1:7890`、`未配置`、`API key`、`异常堆栈`、`docs 为空`）。发现后删除并改写为资料限制。
