# 2026-09-25 AI4S 热点端到端修复复盘

此文记录工程问题和可迁移防线，不提供某条热点的预制研报内容。后续主题必须重新取证。

## 观察到的故障

1. 前一次真实任务完成了阶段 A 证据台账，但主代理提前结束，研报和海报未交付。根因之一是旧编排提示写着“启动 Agent 后告知用户并结束本轮”，与用户要求本轮交付成品冲突；只看后台 Worker 状态或空摘要也会误报“完成”。
2. 长篇 HTML 一次性写入容易耗尽响应或漏掉后半章节；只有骨架及前三章时，任务仍不能算结束。
3. 文件服务本地写入了证据文件，但 SQLite `fileinfo` 表缺失导致登记接口 500，形成“文件存在、服务不可用”的不一致。
4. 真实写作中出现过导语使用额外 `<h2>`、章节标题与九章契约不符，以及台账标题所称来源数量与实际条目数不符。它们不是主题特有问题，单靠提示词难稳定避免。
5. 工具返回空摘要、引用版本重复和长上下文放大模型成本，会让“看似推进”与“产物可验收”脱节。
   本次长报告自查时，主代理反复读取零散行并触发上下文压缩，文件更新远慢于工具/模型调用增长；因此新增按错误类别批量修订与有限重试的成本纪律。
6. 第九章多段追加时首段提前关闭 `<section>`，后续来源表落在章节外；正文已有指向 `#sNN` 的可点击编号，但第九章只有名称/DOI 文本而无可点击原始链接。能从正文跳到表格，不等于能追溯到原始来源。

## 修复与适用边界

- 将长文改为骨架加分段追加，片段使用稳定 `chunk_key`，重复提交应幂等；上一段成功才继续下一段。`finalize=true` 前检查完整产物。
- 改写编排规则：用户要求本轮交付成品时，主代理等待后台结果并核对文件，再进入下一阶段；只有用户只要求“启动”或确需人工审批时，才允许中途收口。
- 在工具层加入不依赖模型的封稿检查：九个 `<h2>` 章节标题与顺序、正文和来源编号集合、HTML 结束标签、未完成标记、海报打印样式。它负责拦住结构错误，不证明科学结论正确；仍须人工/模型依据原文做主张抽查。
- 第九章来源锚点必须留在章节容器内，每条来源提供 http(s) 原始链接；封稿时检查这些结构约束。
- 文件服务启动时初始化数据库，并针对缺表引发的登记失败做接口回归。启动初始化只解决表存在性，不代表所有文件内容可读取。
- 长任务使用文件与状态双证据：既查 Worker 结果，也查报告路径、内容和封稿状态。空摘要先诊断再续跑，不能直接交差。
- 将来源数量、版本关系和引用一一对应列入研究台账验收；标题数字必须来自实际条目而非人工估算。
- 后续封稿审计又发现：只用集合比较来源编号会漏掉重复 `id="sNN"`，只匹配 `https://` 前缀会把没有主机的伪链接误判为原始来源。现按出现次数检查锚点，解析网址并要求 http(s) 主机；海报来源也应用同一有效网址判断。
- 封稿工具仅对会话工作区 `report/` 与 `poster/` 下的 HTML 启用 AI4S 专项检查，因此 skill 与主代理提示词必须明确这两个正式交付路径；任意路径的“文件已写入”不等于通过封稿验收。

## 验收状态与后续回归

本次付费真实任务的运行状态最终为 `SUCCESS`，报告与海报均生成；但独立验收为失败：一级标题 10/9、第四章标题不符、报告 32 条来源没有可点击原始链接、海报没有可点击来源链接，台账标题宣称 S01–S42 而实际只有 32 条，另有 S32 未在正文使用。第九章章节外来源问题已在本次自查中修复，正文 `#sNN` 引文原本可点击；早期只识别方括号的检查脚本曾误报“正文引文缺失”，现已支持两种格式。新封稿规则与 skill 已在该次运行结束后部署，Java、Python 和前端服务可访问，但尚未在部署后再发起一条付费跨主题研报，因此不能宣称端到端稳定通过。后续至少回归：材料丰富的生命科学事件、无可读论文的早期公告、相互矛盾的版本、非生命科学 AI4S 事件、文件登记故障和长文中途恢复；每项同时检查事实溯源、结构、状态与海报一致性，而非只看 HTTP 200。

本轮工程验证还包括完整 `mvn -q test` 通过、文件服务相关 `pytest tests/test_file_manage_api.py -q` 六项通过、skill 格式校验通过；这些证明修复未破坏相应代码路径，不等同于多主题研报质量已经通过。

## 外部方法借鉴（只借原则，不复制内容）

- [OpenAI Build skills](https://developers.openai.com/plugins/build/skills)：缩小触发边界，明确输入、产出和测试。
- [OpenAI Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills)：对输出和执行过程定义可度量检查，并使用正反样例。
- [Agent Skills 规范](https://agentskills.io/specification)：主文件保持聚焦，专题方法放入按需读取的参考文件。
- [Anthropic validate-data](https://github.com/anthropics/knowledge-work-plugins/blob/main/data/skills/validate-data/SKILL.md)：在分享前检查方法、数值分母、结论与证据的一致性。
- [literature-review-skill](https://github.com/pinshuai/literature-review-skill)：借鉴检索日志、去重与引文核验；其固定文献数量适用于系统综述，不能机械套给单事件热点报告。
- [researcher_agent research skill](https://github.com/drader/researcher_agent/blob/main/skills/research/SKILL.md)：借鉴“主张逐项验证”和明确的失败/停止分支；本产品仍需按用户要求自行生成研判结论，不照搬其交付边界。
- [standardhuman deep-research-skill](https://github.com/standardhuman/deep-research-skill/blob/main/README.md)：借鉴可审计的检索日志、来源目录、证据台账和“转载不等于独立来源”；本产品只保留与单个热点相关的最小记录，不机械要求固定查询或论文数量。
- [wentorai in-depth-research-guide](https://github.com/wentorai/research-plugins/blob/main/skills/research/deep-research/in-depth-research-guide/SKILL.md)：借鉴先界定研究问题、记录纳入/排除理由、矛盾与反例检索，以及按主题综合而非逐篇罗列；其中系统综述式穷尽检索与统一证据等级不直接套用于快讯研报。
- [K-Dense scientific-critical-thinking](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-critical-thinking/SKILL.md)：借鉴对实验设计、偏差、统计条件及“研究实际显示什么”的逐项质询；不能把某一学科的 GRADE/临床证据等级当作所有 AI4S 领域的通用分数。
- [Anthropic validate-data](https://github.com/anthropics/knowledge-work-plugins/blob/main/data/skills/validate-data/SKILL.md)：借鉴分母、基线、时间范围、可比性和可视化的交付前复核，将错误分为阻断、带限定交付和可通过；不采用其商业数据分析的字段作为科研成果通用模板。
